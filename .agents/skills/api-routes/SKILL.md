## ルール
- TypeScript を使用する
- `route.ts` は配線のみとする
  - 認証・バリデーション・DB操作などの実処理はすべて別関数に切り出す
  - `route.ts` を配線専用にすることで責務が明確になり、ロジックを単独でテストできる
- エラーレスポンスの message は、権限の無い相手にも返る前提で書く
  - どのステータスでも、内部の構成（ストレージのパス・ファイル名の付け方など）・DB のエラー内容は含めない
  - 401・403 には message を付けない
    - アクセスできない理由（対象の利用企業・判定の条件など）を伝えると、利用者や権限の仕組みを外部に教えることになる
  - 400・404 は、利用者が対処できるよう原因を具体的に書く
    - ただし、利用企業名・判定の条件は含めない
  - 500 は「Internal Server Error」だけを返し、詳細はログにだけ出力する
  - 503 は、アプリが意図して返すもの（DB のタイムアウトなど、時間をおけば成功しうる失敗）に使い、処理ごとに「何ができなかったか」を書く
    - 例：「混み合っているため、商品の件数を取得できませんでした。時間をおいて再度お試しください。」
