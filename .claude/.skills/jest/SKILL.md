name: jest
description: jest を使用したテストコードを実装する。
---

## 骨子となる考え方
- 「このテストが落ちたとき、このファイルのバグだと言えるか？」を基準とする
  - 依存先のバグでテストが落ちるなら、そのテストは不要
- テストは「入力 → 出力・副作用」の振る舞いを検証する
  - mock ばかりのテストは「テストできているつもり」になりやすいため注意する
- 関数の呼び出し順序や、throw による自然な帰結はテストしない
- 既に別のテストで保証されているロジックは再テストしない

## ルール
- アサーションは結果に向ける
  - res.status, res.data などのレスポンスを主な assert 対象とする
  - 関数が「何を引数で呼ばれたか」ではなく「何が返ったか」を見る
- mock 関数のアサーション
  - toHaveBeenCalled / not.toHaveBeenCalled は分岐がある場合のみ使う
    - 「分岐によって呼ばれる/呼ばれないが変わる」場合にのみ意味がある
    - 分岐のないフローや throw の自然な帰結として呼ばれないのは自明なので書かない
    - 分岐のないフローで mock 関数の呼び出し有無をテストしない
  - toHaveBeenCalledWith は副作用の内容確認（DB への書き込み内容等）に使う
    - 呼び出しフローの確認目的には使わない
- モックは到達させたい分岐のセットアップ目的に限定する
  - mockRejectedValueOnce 等は「その条件下でルートがどう振る舞うか」を見るためのもの
  - 何を throw/resolve させるか自体はテストの関心ではない
- 共通処理は再テストしない
  - ルートのテストは「そのルート固有のロジック」だけを対象とする
- beforeEach で jest.clearAllMocks() を呼ぶ
  - テスト間でモック状態が汚染されないようにする
- describe / it の構成
  - describe はテスト対象の単位（関数名・エンドポイント）
  - it の名前は「〜の場合は〜を返す」形式で振る舞いを記述する
- it の単位
  - 1つの it で1つの振る舞いを検証する（複数の関心事をまとめない）
  - ロジックの分岐ごとに it を設ける（分岐の数 = テストケースの最小数）
